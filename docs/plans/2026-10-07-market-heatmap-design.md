> （另一項）：只依賴它交付的 `price_change` 欄位語意與「除權息日不得暫存 0」，不依賴它的做法，也不需要它提供任何通知；需求集中
> 寫在第 1 節「對除權息漲跌修正的需求」。實作計畫等該項設計定案（採納這些需求）後再拆。2026-10-23 六輪修訂，見「審查紀錄」。

## 背景

這是功能路線圖第 4 項。App 裡跟「整個市場今天怎麼了」有關的畫面：

- 今日頁「族群排行」：產業卡片，看各產業成員報酬的**中位數**（今日／20 日／5 日／轉向）。
- 產業概覽頁：各產業與檔數。
- 大盤總覽頁：指數、漲跌家數、情緒、法人、融資券。

都看不出「誰的權重大、今天誰撐盤、誰拖盤」。熱力圖用一張圖回答：每檔一格、依產業分區、面積是市值、顏色是當日漲跌。

## 目標與成功標準

- 獨立頁，從大盤總覽頁進入；上市、上櫃各一張圖（分別對應加權指數與櫃買指數）。
- 面積＝市值，顏色＝當日漲跌（漲紅跌綠）。
- 收盤後，除了沒有今日漲跌的股票（空心），整個市場都有顏色；盤中畫面上最大的 69 格每 15 秒即時更新；收盤後約 4 分鐘內整個市場
  換成今日收盤（大格子先），不必等盤後資料寫入。
- 小產業可以放大看清楚。
- 不新增資料表、不新增資料來源；盤中沿用既有報價中心，不改它的行為。
- 守專案原則：本地優先、不接付費服務、文案不給投資建議（`no_investment_advice_copy_test`）。

## 非目標

- 顏色不切換 5 日／20 日（多日的產業強弱由族群排行負責）。
- 面積不用成交值。
- 不改報價中心（`LiveQuoteCenter`）；盤中不做「前段必抓、其餘輪替」的分層登記。
- 熱力圖不自行修正除權息日的漲跌：由「除權息漲跌修正」負責，全 App 共用同一個欄位（熱力圖自己算一套，同一檔就會在熱力圖與
  其他畫面顯示不同漲跌）。
- 不放主選單或側邊捷徑：路線圖第 5 項（Mac 導覽）一起設計，避免導覽改兩次。
- 不含 ETF、上櫃 ETF、存託憑證、興櫃股。
- 產業名稱不翻譯（與產業概覽頁、掃描頁的產業篩選相同，英文介面也顯示資料庫裡的中文產業別）。
- 熱力圖不進評分、不寫資料庫。

## 設計

### 1. 資料與計算

**納入範圍**（每個市場一張圖）：產業不是 ETF／上櫃 ETF／存託憑證、該市場最新交易日有收盤價、有可用的股數。這個條件同時排除
了興櫃（10/23 資料庫裡的興櫃股都沒有價格；興櫃期間就有價格的情況見已知限制）與停牌／無成交（當天沒有價格）。

**日期與「已有今天正式資料」**：某市場在 `market_day_fetch` 有今天的 `prices` 紀錄，才算有今天的正式資料；否則用該市場有
`market_day_fetch` 紀錄的最近一個交易日。不用裸 `MAX(date)`：逐檔回補只寫了幾檔今天的價格時，裸 `MAX` 會讓整張圖切到幾乎空白
的「今天」。頁首標示資料日期，例如「10/6 收盤」。

**市值**＝收盤價 × 已發行股數。股數規則：

- 上市：只用外資持股的股數（每天、全市場）。
- 上櫃：取兩個來源中日期較新的一筆；同一天時用外資持股。兩個來源都有、最新一筆相差超過 10%（以較大的一方為分母）時，不畫，計入
  頁尾。
- 股數只決定面積，不影響顏色。

**漲跌幅**＝`priceChange / (close − priceChange)`，與大盤統計同一公式。漲跌價差是空值、或分母 ≤ 0 時，該格是空心「無漲跌資料」，
**不退回前一筆收盤**：不可沿用 `PriceCalculator.calculatePriceChange` 的退回邏輯（除權息日退回前收盤會把股息算成跌幅，減資恢復
買賣日會出現 −70% 這類數字）。不比價日（除權息、減資、面額變更）的值是否正確由「除權息漲跌修正」負責；該項完成前，除權息日上市
多為 0（畫成平盤）、上櫃為空值（空心）；減資、面額變更恢復買賣日上市為 0、上櫃已有值。

**對除權息漲跌修正的需求**（熱力圖只依賴這兩點，不依賴它的做法，也不需要它提供通知——補正何時寫入，熱力圖都靠下方「重讀資料庫
的時機」的內容指紋偵測；該項的設計要逐條採納，做不到時回頭改本節）：

1. **語意**：`daily_price.price_change`＝收盤 − 交易所當天的平盤價（開盤競價基準）。某檔某日的平盤價不明時為空值，不得為 0。
2. **除權息日的不變式**：任何寫入 `daily_price` 的 transaction 提交後，交易所當天列為除權息（含只有現金增資的除權）的那一列，
   `price_change` 只能是正確值或空值，不得暫存 0（0 與真的平盤分不開，熱力圖會把它畫成平盤；台積電除息日占上市圖約 41%）；已經
   正確的列被覆寫時仍須正確（例如 21:30 重寫不得把補正過的值改回空值或 0）。

上市的減資、面額變更恢復買賣日，以及上市新股首日（含轉上市首日），不在本節兩條需求內：它們的平盤價（承銷價、轉市場前的基準
等）目前沒有已知來源，列為已知限制（上櫃這兩類日子本來就有值；轉上市首日的基準推論為上櫃最後一天收盤，未驗證）。除權息有候選來源——上市看除權除息結果表的「開盤競價基準」，上櫃看「開始交易基準價」或每日行情的「次日
參考價」——但都還沒驗證是不是交易所算漲跌用的平盤價（含只有現金增資的除權），由除權息漲跌修正查證。

補正不得為了通知熱力圖而改動 `market_day_fetch`：它的 `fetched_at` 是定案判斷的依據，改了可能讓未定案的日子被當成已定案、之後
不再重抓。

**產業分組**：用股票主檔的產業別，上市、上櫃各自的分類。產業的漲跌是成員漲跌（上面的公式，空值的成員不計）的**市值加權**平均，近似這個產業對指數的影響（除息日不含除息
對指數的扣點，見已知限制）；這和族群排行的成員中位數是不同指標，圖例寫明「產業漲跌為市值加權」。產業別空白的歸到「未分類」（目前沒有這種股票，純防禦）。

**頁尾**：只計我們自己的資料缺口：「N 檔缺股數或股數不一致，未列入」，沒有時不顯示。興櫃、停牌、無成交不計——那是市場本身
的狀況。

**結構**：兩個純函式，都不寫資料庫。

- 分組計算：輸入股票、價格、股數、漲跌來源，輸出各產業與各檔的市值、漲跌。
- 佈局：輸入分組與圖區大小，輸出矩形。

盤中與收盤後共用同一套，只換漲跌來源。開頁時讀資料庫算一次；資料讀取加計算超過 100ms（debug 量測）就把計算移到背景 isolate。

**重讀資料庫的時機**：開頁；`dataUpdateEpochProvider` 通知；`liveQuoteBoundaryProvider` 換值（跨午夜、開盤、收盤）；以及**頁面可見
期間每分鐘比對一次內容指紋**，任一項不同就重讀。

- **指紋**：兩個市場各一組——`market_day_fetch` 該市場 `prices` 的最新資料日，以及該日該市場 `daily_price` 的列數、`price_change`
  非空的列數、`price_change` 合計、`close` 合計（join `stock_master` 依市場過濾）。
- **為什麼輪詢**：launchd 在背景寫入時沒有通知。
- **為什麼比對內容**：很多寫入不改日期——15:30 覆寫前一日（10/23 颱風停市實例）、一般交易日 21:30 覆寫 15:30 寫過的同一天、逐檔回補、日後的
  除權息補正；`market_day_fetch` 也不記逐檔與未達門檻的寫入。比對內容不必知道是誰在什麼時候寫的，也不碰定案判斷。
- **成本**：查詢走 `idx_daily_price_date_symbol` 索引，每個市場一次約 0.5～0.7 毫秒（兩次量測；10/22：上市 1,233 列、上櫃 907 列）。
- **讀取順序**：先讀指紋、再讀資料，重讀後以讀資料前取得的指紋為新的比較基準；寫入若夾在兩者之間，下一次比對會再重讀一次，不會漏。
  重讀進行中又有任何觸發（通知或輪詢），結束後再讀一次，只排一次，不丟棄。
- **頁面不可見時不輪詢**，回到可見時立即比對一次。
- **指紋查詢失敗**時保留現有畫面、下一分鐘再試，不顯示錯誤卡片（錯誤卡片只用在開頁讀不到資料）。

### 2. 畫面與互動

```
┌ 大盤熱力圖 ──────────────── [上市｜上櫃] [產業 ▾] ┐
│ 加權 xx,xxx ▲xx（+x.xx%）              10/6 收盤        │
│ 色階：跌 … 0 … 漲 ｜ 雙線框＝自選或持股 ｜ 空心＝沒有今日漲跌 │
│ 產業漲跌為市值加權                                       │
├────────────────────────────┬─────────────────┤
│ 半導體業 +x.x%              │ 電子零組件業 +x.x% │
│ ┌────────────────┐┌───┐ │ ┌────┐┌───┐   │
│ │ 台積電              ││   │ │ │    ││   │   │
│ │ +x.x%               │└───┘ │ └────┘└───┘   │
│ └────────────────┘ …    │ 金融保險業 …       │
└────────────────────────────┴─────────────────┘
  3 檔缺股數或股數不一致，未列入
```

**頁面**（由上而下）：

1. 標題列：上市／上櫃切換（樣式同大盤總覽手機版）、產業選單。
2. 頁首：該市場指數點數與漲跌（與大盤總覽同一來源、同一標示方式）、熱力圖的資料時間或盤中狀態（第 3 節）。指數與熱力圖的資料
   來源不同，各自標示。
3. 圖例：色階、自選框、空心格子的意思、「產業漲跌為市值加權」。
4. 熱力圖占滿剩下的高度、不捲動。
5. 頁尾：資料缺口檔數（有才顯示）。

**入口**：大盤總覽頁標題列加一個按鈕。不動主選單。

**熱力圖**：

- 兩層 squarified：先依產業總市值切產業區塊，再在區塊內依個股市值切格子。
- 產業區塊頂端一條標題列，例如「半導體業 +1.8%」；區塊太小放不下時不畫標題列。
- 格子文字依大小：大格顯示名稱＋漲跌幅、中格只顯示漲跌幅、小格不顯示。
- 自選或持股的格子加**雙線框**（外深內淺各 1px）：任何填色上都看得見；單色主題色框的亮度與平盤灰、深紅幾乎相同。

**色階**：

| 漲跌幅（絕對值） | 0 | (0, 0.5) | [0.5, 1.5) | [1.5, 3) | [3, 5) | [5, 9.5) | ≥ 9.5 |
|:--|:--|:--|:--|:--|:--|:--|:--|
| 階 | 平盤 | 漲／跌 1 | 2 | 3 | 4 | 5 | 6 |

- 平盤只給剛好 0%，填中性灰；其餘依方向從股價色（`PriceColors`）推導，幅度越大越顯眼：每一階對頁面底色的對比不低於前一階
  （深色主題越亮、淺色主題越深）。分界點依「量測」的分布訂，9.5% 與大盤總覽漲跌停家數的門檻相同。圖例最深一階寫「≥ 9.5%」：
  上櫃新股首日的漲跌以承銷價為基準，會出現 +100% 以上，不是只有漲跌停（例：7825 +123.93%、7856 +110.22%）。
- 格子文字只用純黑或純白，每一階取對比較高的那個，兩種主題都要 ≥ 4.5。填色要避開「黑字白字都到不了 4.5」的亮度帶（相對亮度
  約 0.16～0.22），定色時以測試把關。
- 用固定色階而不用連續漸層：色數有限，每個都能測文字對比。

**空心格子**＝沒有可用的今日漲跌：盤中未即時（第 3 節）、尚無成交（只有買賣報價）、無報價、尚未取得收盤報價、或無漲跌資料。
只畫細灰邊、不填色、文字變淡，與平盤的實心灰分開；提示寫明是哪一種。變淡的文字對頁面底色也要 ≥ 4.5。平盤灰、第 1 階與空心
三者要分得開（以對比測試把關）；小到只剩幾像素的格子分不開，列為已知限制。

**互動**：

- 點格子 → 個股頁。
- 滑鼠移上去（桌面）或長按（手機）→ 浮出提示：名稱、代號、價格、漲跌幅、市值（億）。空心格子另寫原因；盤中未即時的附上一交易日
  收盤漲跌並標日期，例如「10/6 收盤 −0.8%」（同樣用上面的公式，空值時不顯示、不退回）。
- 點產業標題或從產業選單選 → 放大到只畫那個產業，標題列出現「← 全市場」；切換市場時回到全市場。產業選單依市值排序、列出各產業
  漲跌，是小產業唯一的放大入口（它們在全市場圖上放不下標題列）。

**繪製**：全部格子用一個 `CustomPainter` 畫（上千個 widget 太重）；點擊與滑鼠位置以矩形查找對應格子；格子小到不到幾像素時照畫、
但不回應點擊與滑鼠。提示畫在獨立的一層，滑鼠移動不重畫整張圖。

**無障礙**：全市場圖每個產業一段描述（例如「半導體業，市值加權上漲 1.8%，共 N 檔」）；放大到單一產業時才給每一格描述（例如
「台積電，上漲 1.2%」）。上千段描述讓螢幕閱讀器無法使用。

**文案**：畫在圖上的字、提示、無障礙描述的固定文字一律放翻譯檔（`zh-TW.json`、`en.json`），讓文案守門測試掃得到；寫死在 Dart 的
字掃不到。

### 3. 盤中即時

頁面以 `LiveQuoteScope` 登記，該市場指數一律登記。

| 時段 | 登記 | 面積 | 顏色 | 頁首 |
|:--|:--|:--|:--|:--|
| 開盤前、休市日 | 不需要即時 | 最新正式資料 | 全部用最新正式資料 | 「10/6 收盤」 |
| 盤中 9:00–13:30 | 畫面上最大的 69 格（全市場：該市場市值前 69；放大：該產業市值前 69） | 前一交易日收盤市值，盤中不變 | 登記的、有成交的用即時；其餘空心 | `LiveQuoteStatusRule.header` |
| 收盤後、該市場還沒有今天正式資料 | **滾動登記**：還沒拿到收盤報價的股票中，依市值取前 69；放大與否都一樣 | 同上 | 有今日收盤報價的用收盤報價；其餘空心 | 熱力圖自己的彙總（見下） |
| 該市場有今天正式資料後 | 不需要即時 | 今日收盤 | 全部用資料庫；漲跌價差空值的格子空心（含補正前的除權息股） | 「10/7 收盤」 |

**盤中**：

- 69＝2 批扣掉指數：維持每 15 秒一輪。上市前 69 約占 85% 面積、上櫃約 69%。
- 放大到小產業時整個產業都即時，放大在盤中也有用。
- 只用熱力圖自己登記的股票上色；中心裡別的畫面抓過的報價不用（可能是早上的舊價）。
- 只有買賣報價、沒有成交的股票（試撮或五檔中價）不上色，空心「尚無成交」：中價不是真的漲跌。
- 漲跌幅以證交所即時資料的昨收（`y`）為基準。一般交易日 `y`＝前一日收盤＝漲跌停的計算基準：`test/fixtures/twse_mis_intraday.json`
  與 `twse_mis_intraday_limit_locked_20261005.json` 共 13 筆（11 檔、兩個交易日），漲跌停價（`u`／`w`）都恰好等於 `y` × 1.1／0.9 依升降單位取整，`y` 也都
  等於資料庫的前一交易日收盤（實測）。**除權息、減資、面額變更恢復買賣日的 `y` 是否等於開盤競價基準尚未驗證**：這 13 筆都不是這類
  日子。盤中顏色是熱力圖自己的依賴，由本設計驗證（見「驗證」第 0 項）。

**收盤後滾動登記**：

- 每次只登記「還沒拿到收盤報價」的前 69 檔，報價中心每輪 2 批、15 秒；拿到收盤報價的移出、下一批補進。上市約 16 輪、上櫃約 13 輪，
  約 4 分鐘填滿，大格子先。
- 不一次登記整個市場：那會排成 31 批的一大輪——要從上一輪開始等 232.5 秒才開始、一輪約 7 分鐘、全部回來才套用、等待期間累積
  暫停計時而可能誤報「報價暫停」、被限流或 App 變不可見時整輪作廢。滾動登記每輪都是 2 批，這些問題都不會發生，也不用改報價中心。
- 收盤報價不論是哪個畫面抓的都可以用（收盤報價是定值）；不是收盤報價的一律不用。
- 整天沒有成交的股票拿不到收盤報價：報價中心試滿 10 次後不再抓，它們留在名單裡，只會讓那一輪少抓幾檔（每個市場每天約十幾檔）。
- 頁首：「今日收盤 N／M 檔・待盤後更新」（M＝圖上的檔數），加上報價暫停、限流等既有狀態。不沿用 `LiveQuoteStatusRule.header`
  的收盤後分支：全市場一定有沒成交的股票，它會一直顯示「最後報價 ＜早上的時間＞」。

**盤中產業漲跌**：只用已即時的成員算市值加權漲跌，旁邊標即時部分占的市值比例，例如「半導體業 +1.8%・即時 96%」。一檔都沒有即時的
產業顯示「未即時」。產業選單照同一規則。收盤後滾動期間同樣處理（標已取得收盤的比例）。

**失敗時**：報價暫停、限流、證交所尚無報價都顯示在頁首；格子維持最後一次拿到的顏色，不清空（與自選卡片一致）。即時的任何錯誤都
不影響正式資料的顯示。

### 4. 邊界情況

| 情況 | 處理 |
|:--|:--|
| 完全沒有收盤資料（剛安裝、還沒更新過） | 空狀態：「完成第一次資料更新後就會顯示」 |
| 讀資料庫失敗 | 錯誤卡片＋重試（樣式同大盤總覽頁） |
| 上市、上櫃資料日期不同 | 各自標日期，切市場時頁首日期跟著變 |
| 只寫入一部分股票的日子（逐檔回補） | `market_day_fetch` 沒有當天紀錄 → 不當成當天的正式資料 |
| launchd 在背景寫入、App 在前景 | 頁面可見期間每分鐘比對內容指紋，有變就重讀 |
| 交易日 15:30 時每日行情還沒換日（推論，未見實例） | 15:30 那輪寫的是前一日；當天維持收盤後的即時顯示，21:30 寫入後切回資料庫 |
| 上櫃全市場行情連線失敗、上市價格也沒寫入 | 兩個市場都沒有當天紀錄，維持收盤後的即時顯示；之後哪一輪寫入就由指紋偵測切回 |
| 有收盤價但缺股數、上櫃兩來源股數相差超過 10% | 不畫，頁尾計數 |
| 漲跌價差空值、分母 ≤ 0 | 空心，提示「無漲跌資料」 |
| 產業別空白 | 歸「未分類」 |
| 格子小到點不到 | 照畫，不回應點擊與滑鼠；放大產業後才點得到 |
| 視窗縮放、主題切換 | 佈局重算（純函式），顏色跟主題 |
| 盤中登記的股票停牌、無報價、尚無成交 | 空心，提示寫明原因（沿用報價中心逐檔狀態與顯示來源） |
| 漲跌停鎖住 | 即時漲跌幅 ±10%（依跳動單位最少約 9.89%），落在第 6 階 |
| App 開著跨午夜、開盤、收盤 | `liveQuoteBoundaryProvider` 換值時重讀資料庫、重算登記與標示 |
| 收盤後滾動中被限流或 App 變不可見 | 只損失進行中的一輪（≤ 2 批），恢復後從還沒拿到的繼續 |

## 已知限制

- 盤中只有畫面上最大的 69 格即時；小型股要放大到所屬產業才會即時。
- 只有董監表一個股數來源的上櫃股（約 570 檔），遇到公司行動空窗（股數已變、價格還沒變）時面積會錯，無法偵測。
- 15:30 第一次寫入可能缺部分股票的收盤價，之後的定案重抓才補上；這段期間那些股票不畫，也不計入頁尾。
- 小到只剩幾像素的格子，空心、平盤、第 1 階分不出來。
- 創新板股票照常納入（上市散在一般產業；上櫃是單檔產業「創新板股票」）。
- 手機上換頁動畫或返回手勢期間，下層頁面可能短暫重新登記，打斷進行中的一輪（只損失一輪）。
- 交易日曆漏標的休市日：收盤後每檔都要試滿 10 次「有回應但不是今天」才停，約數百個請求、四十分鐘左右，有上限。
- 台積電約占上市圖 41% 面積，小產業要放大才看得清楚。
- 除息日產業漲跌不含除息對指數的扣點：加權指數遇現金除息不調整基值，除息股的現金股利會讓指數開盤直接扣點（例：
  2025-06-12 十檔除息，新聞報導指數開盤約減少 42 點、其中台積電約 36 點）；除權息漲跌修正完成後，熱力圖每格是對平盤價的漲跌，
  所以除息日的產業漲跌與指數漲跌會有落差。
- 漲跌價差是空值的日子，熱力圖畫空心，其他畫面（經 `PriceCalculator`，或投資組合自己的退回）卻退回前一筆收盤，兩邊顯示不一致；
  全 App 要不要停止退回，由除權息漲跌修正決定。
- 若熱力圖比除權息漲跌修正先上線：除權息日上市股畫成平盤、上櫃股空心（台積電除息日占上市圖約 41%）。
- 上市的減資、面額變更恢復買賣日，以及上市新股首日，盤後畫成平盤（資料庫記 0）：它們的平盤價目前沒有已知來源，每日第一次寫入的
  端點也沒有標記，不在「對除權息漲跌修正的需求」內，由該項自行決定怎麼處理。盤中這幾類根本不在圖上：前一交易日沒有收盤價（新股
  還沒掛牌、減資期間停止買賣），不符合納入範圍。
- 轉市場的股票：股票主檔的市場別每輪依價格來源覆寫（讀碼），所以轉換當天在當天正式資料寫入前仍在原市場的圖上（即時報價的市場
  前綴也跟著主檔，推論會抓不到報價而顯示空心），寫入後換到另一張圖，上市首日記 0、畫成平盤。例：8908 欣雄 10/16 轉上市。
- 上櫃新股在任一股數來源（見現況）收到它之前不畫、計入頁尾。例：7806 10/15 上櫃，10/22 兩個來源都沒有。
- 推論：興櫃股若在興櫃期間就有價格（例如加入自選後被逐檔補價；主檔也標上櫃），會被當成上櫃股——沒有股數時計入頁尾的「缺股數」、
  有股數時畫成空心格，兩種都不是我們的資料缺口，也與非目標「不含興櫃股」不符。10/23 資料庫沒有實例；上櫃新股掛牌前的價格是掛牌後
  才補進的（例：7806 的 253 列是 10/15 21:30 掛牌當晚補進，log），熱力圖只看最新交易日，不受影響。
- 股數在價格之後才寫入（外資持股、董監持股、上櫃逐檔持股都排在每日價格寫入之後；10/23 那輪價格 15:30:09、外資持股 15:30:14）：
  輪詢若落在中間，會用新價格配舊股數重讀，之後股數的寫入不改指紋，要等下一次觸發（例如 App 內更新完成的通知、跨午夜、重開頁面，或之後
