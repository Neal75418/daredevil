# 收盤摘要（設計）

日期：2026-11-20

## 為什麼

使用者收盤後要決定「明天要不要買賣自選裡的股票」，判斷依據是自己的交易決策表 v3（以下簡稱 v3）。2026-10-05 收盤後，使用者請人手動做過兩次：13:40 一份收盤結論（大盤、族群、自選整體、持股損益），17:50 一份盤後籌碼（三大法人、外資與投信個股動向、自選股的法人動向）。

那兩份內容的數字 App 大多已經有，但分散在四個地方：大盤總覽（指數、漲跌家數、成交金額、三大法人、融資、綜合判讀）、今日頁的族群排名（今日、5 日、20 日）、法人排行（外資與投信買賣超各前 50、連買天數）、自選頁（每檔漲跌）。App 沒有的是：**把 v3 的條件套在每一檔自選股和持股上，一頁看完今天誰的條件變了。**

## 目標

1. 一個「收盤摘要」頁：持股與自選股每檔一列，照 v3 標出今天的狀態與事件。
2. 最上面一行大盤油門（v3 第零層），其餘大盤資訊連到大盤總覽，不重複。
3. 持股列出成本、損益、停損價與時間停損的進度（見「持股」一節）。
4. 只用正式盤後資料（每日更新寫入的價格、法人、指數），寫明資料日期與法人資料到了沒。
5. 今日頁上方放入口卡，寫著資料日期、持股檔數、有事件的檔數。

## 非目標

- 每週摘要、歷史摘要（看前幾天標了什麼）：不在「決定明天要不要動」的用途上。
- 推播通知、盤中版本（v3「盤中不算數，收盤才定案」）。
- v3 裡算不出來或要隔天才知道的：結構 A（恐慌低點，是大盤層級的判斷）、油門的解除條件（指數走完結構 C）、結構 B 門檻滾動上移、進場價窗、次日條件進場、熔斷（回撤 12% 或連虧 8 筆）、部位大小（R 與部位上限需要帳戶總額）。
- 不把 App 既有的規則評分（今日頁三種模式）混進這頁。
- 融資餘額：v3 沒有用到。

## 反目標

- 畫面上不出現「買進」「賣出」「推薦」這類字眼，只寫條件與事件（例如「雙章齊」「連 2 日收破月線」）。判斷由使用者做；這類字眼若日後分享出去也會落在投顧業務的範圍。
- 不用盤中即時報價補洞：資料還沒到就寫還沒到，不拿不同來源拼成一份。

## 做法比較

| 做法 | 內容 | 結果 |
|:--|:--|:--|
| 1. 新頁，打開時用資料庫現算 | 讀價格、法人、指數、營收、自選、持股，套 v3 條件 | **使用者選定**。資料分段到（價格與上櫃法人 15:30、上市法人 16:00 後公布要等之後的輪次、融資 21:30），現算永遠反映已到的部分；不改資料表、不動 launchd CLI。59 檔 × 約 80 個交易日，計算量很小 |
| 2. 每日更新後由 CLI 產生、存進資料庫 | 新資料表存每日摘要 | 可以留歷史，但要加表與遷移、每段資料到時都要重產、CLI 鏈只能純 Dart；歷史不在用途上 |
| 3. 標記直接加在自選頁每列 | 不加新頁 | 自選頁盤中跟著即時報價變，混進收盤才定案的標記違反 v3；59 列各多一行太擠，也沒有一眼看完的地方 |

## 使用者已決定的事

- 用做法 1。
- 事件照 v3 標（使用者確認現在判斷隔天買賣仍照 v3 那幾條）。
- 使用者開始在 App 的投資組合記買賣（目前投資組合沒有任何紀錄），摘要據此算持股這一側。
- 每週版先不做。
- v3 原文（決策表）已不在，以下三項由 App 程式裡引用的 v3.3／v3.4 條文、2026-08-07 停損回測，加上本機資料的量測補齊，使用者同意：
  - 持股停損與時間停損照 v3.3（見「持股」）。
  - 籌碼章加買超下限；「單日大額反向」定為另一方一天賣掉籌碼章那方三天買的量（見下表）。
  - 強者榜上沒持有的股票不做守門價，除名照用「連 2 日收破月線」。

## 資料與時間

- 資料日 D：`daily_price` 的最新日期（兩個市場合計）。每日更新在交易日 15:30 與 21:30 執行；15:30 那次寫入當天價格與上櫃法人，上市法人 16:00 後才公布，要等之後的輪次。交易日 16:00 以前打開、D 還是前一個交易日時，頁首寫「今天的資料 15:30 更新後才有」；過了 16:00 還沒更新到，寫「資料落後：最新是 {日期}」。
- 分市場判斷資料到了沒（上櫃全市場行情常在傳輸中被切斷，只寫入一邊）：某個市場在 D 沒有價格，那個市場的股票寫「行情未到」；市場有資料、只是這檔 D 沒有成交，寫「資料日沒有成交」。兩者都不標事件。
- 法人：某個市場在 D 沒有法人資料時（例如更新還沒跑完），頁首寫哪個市場未到，那些股票所有用到法人的條件標「法人未到」，不拿前一日的資料頂替。
- 指數：`market_index` 名稱為「發行量加權股價指數」的收盤；最後一筆不是 D 時油門寫「加權指數未到」。
- 價格用資料庫的原始價（未還原除權息），與 App 的均線提醒、守門價提醒（`AlertTargetCalculator`）及一般看盤軟體預設的均線同一口徑：摘要說「收破月線」時，提醒那邊算的是同一條線。代價是除權息日的缺口會算進近月漲幅與均線；強者榜型的股票殖利率低，影響小，列為已知限制。
- 減資、分割這類大缺口沿用 `price_continuity.dart` 的斷點偵測，只用斷點之後的資料。斷點之後天數不夠某條條件的回看長度時，該條顯示「資料不足」，並當成未通過（不會因此湊成 4/4 或雙章齊）。
- 漲跌幅用資料庫的漲跌（收盤 − 當天平盤價），除權息日不會被算成下跌。
- 張數＝股數 ÷ 1,000（價格與法人資料的單位都是股）。

### 頁首

- 資料日與法人資料狀態。
- 油門（v3 第零層，對象是加權指數）：
  - 月線＝含 D 在內的 20 日收盤平均；5 日門檻＝D 之前 4 個交易日的收盤平均。
  - D 收盤低於 5 日門檻→「空手」；否則低於月線→「小量」；否則「全開」。
  - 另列「最近一次收破 5 日門檻」的日期與距今交易日數：v3 的空手要等指數走完結構 C 才解除，App 不判斷解除，使用者據此自己判斷空手是否仍有效。
- 「大盤總覽 →」連結。

### 區段與排序

- 第一段「持股」：投資組合裡數量大於 0 的股票，不論是否在自選。
- 之後照使用者的自選分組排序（`watchlist_groups.sort_order`），「未分組」放最後。持股已列在第一段的，不在分組裡重複。
- 段內：有「待處理」事件的在前，再依今日漲跌幅由高到低。

### 分組在 v3 裡的意義

- 以分組名稱辨認：名稱是「強者榜」的分組就是 v3 的強者榜；「除名重審」「大盤溫度計」同理。找不到名為「強者榜」的分組時，頁首寫明「找不到『強者榜』分組，強者榜相關事件不標」，不讓事件無聲消失；此時「符合強者榜入選條件」也不標（否則改名那組的成員會全部被標）。
- 除名重審：v3 的掃描一律排除這組，所以不標進場這一側的事件（結構 B／C、雙章齊）；仍標「符合強者榜入選條件」，那正是重審要看的。
- 大盤溫度計（目前是台積電）：不標個股事件，只寫月線攻防（收在 20 日均線上或下、第幾天）。

### 事件分兩類

- **待處理**：會讓使用者明天做點什麼的——持股收破停損價、時間停損到期、強者榜連 N 日收破月線、符合強者榜入選條件（不在強者榜）、雙章齊、結構 B／C 觸發、觸發日降級、族群退燒。排序與入口卡的「事件 n 檔」只算這一類。
- 對做不是事件，是籌碼章旁的註記（「籌碼章 ✓・對做 → 暫緩」）：外資與投信對作在台股很常見，10/6～11/19 的 30 個交易日裡，籌碼章成立的情況約 29% 會被標到，當成事件會蓋過其他事件。
- **資訊**：漲停、跌停、漲停但外資賣超。只顯示，不排序、不計數。外資與投信方向相反不另外標：列上已經寫了兩方的買賣超；11/10～11/19 自選 59 檔每天有 18～42 檔方向相反，標了等於沒標。
- 事件標的是「目前成立」，不是「今天才轉成立」：使用者還沒處理（移組、出場）前，每天都會看到。結構 B／C 本身就是當天的觸發，只在觸發那天標。
- 上線前用 11/10 以後的資料量一次每天「待處理」的檔數；多到失去排序意義時回頭調整分類，不直接上。

### 每一列

名稱、代號、收盤、漲跌幅、成交量（張）；外資與投信當日買賣超（張）與連買／連賣天數；強者榜條件符合幾條；20 日乖離；事件。持股另加成本、股數、損益（元、%）、停損價與距離、持有天數。點一列進個股詳情。

## v3 條件的計算

所有門檻放在 `lib/core/constants/` 的新參數檔，不寫死在程式裡。「交易日」以該股有價格資料的日子計。

| v3 | 計算（以資料日 D 為準） | 畫面 |
|:--|:--|:--|
| 強者榜入選四條件 | ① 近月漲幅＝D 收盤 ÷ 20 個交易日前收盤 − 1 > 15%；② 近 20 個交易日有漲停（`PriceLimit.isLimitUp`，以收盤漲跌幅判斷）；③ 20 日均量 > 3,000 張；④ D 收盤 > 20 日均線 | 「強者榜條件 n/4」，後面直接列出未通過的條件。不在強者榜分組但 4/4 → 事件「符合強者榜入選條件」 |
| 降級：連 2 日收破月線 | 從 D 往回數，連續收盤低於當日 20 日均線的交易日數 N ≥ 2 | 強者榜分組的股票 → 事件「連 N 日收破月線」（使用者還沒移組前每天都標） |
| 族群退燒（v3 原文是同族群多檔同日破守門價；非持股沒有守門價，以月線頂替） | 同一產業（`stock_master.industry`）有 2 檔以上自選股在 D 由均線上收到均線下 | 這幾檔都標「族群退燒：產業名」 |
| 籌碼章 | 外資在 D 與前 2 個交易日每天買超，且每天買超 ≥ 當天成交量的 1%；或投信同樣條件。不設下限時買 1 張也算，10/6～11/19 自選 59 檔每天中位數 26 檔成立，設 1% 後是 15 檔 | 「籌碼章 ✓（外資連 N）」 |
| 對做（v3：單日大額反向） | 籌碼章成立的那 3 天裡，另一方（外資成立看投信、投信成立看外資）任一天的賣超張數 ≥ 籌碼章那一方這 3 天的買超合計，也就是一天就賣掉對方三天買的量、籌碼章的證據被抵銷。比過以成交量比例定「大額」：10/6～11/19 籌碼章成立 459 次，此定義標出 135 次（29%），「賣超 ≥ 當天成交量 10%」標出 273 次（59%）、「≥ 20%」151 次（32%）；選這個是因為意思直接、不必另訂百分比，標出比例也最低 | 籌碼章旁註記「對做 → 暫緩」，不是事件 |
| 價格章：結構 C 突破 | D 收盤 > D 之前 20 個交易日的最高價（與 App 的「突破 20 日高」提醒同一條線） | 事件「結構 C 突破（突破日不進場）」 |
| 價格章：結構 B 強勢回測 | 近 20 日漲幅 > 0 且 D 收盤 > 10 日均線；支撐取 5／10／20 日均線，任一條滿足 D 最低 ≤ 支撐 × 1.015 且 D 收盤 ≥ 支撐 × 0.995 | 事件「結構 B 回測 10 日線」（寫出是哪一條） |
| 觸發日跌逾 5% 降級 | D 觸發結構 B 或 C，且 D 漲跌幅 ≤ −5% | 事件「觸發日收跌逾 5%，降級」，該結構不算成立 |
| 進場前提 | 會動：60 日漲幅 > 0；乖離：(D 收盤 − 20 日均線) ÷ 20 日均線 < 15%；年增 3 月均 > 30%（`yoy3mAvg`）；D 成交量 > 3,000 張 | 未過的列出來 |
| 雙章齊 | 價格章成立（B 或 C，且未降級）＋籌碼章＋進場前提全過＋沒有對做 | 事件「雙章齊（次日條件另看）」 |
| 其他 | 漲停、跌停（`PriceLimit`）；漲停但外資賣超 | 資訊（不排序、不計數） |

## 持股

- 持股來自投資組合（`portfolio_position` 數量 > 0）；成本用它的平均成本。
- 進場日：目前這段持有（上一次數量歸零之後）最早一筆買進的日期。
- 停損價（v3.3 §4.1 的守門價）＝平均成本 − 2.0 × ATR(20)。ATR 是 True Range 的簡單平均，以進場日為最後一天往回 20 天算，之後固定不動（v3.4：+1R 不移到成本）。倍數與週期沿用 `AlertParams.stopGateAtrMultiple`、`stopGateAtrPeriod`，與個股頁的守門價提醒同一口徑；ATR 的算法與 `AlertTargetCalculator._atr` 相同（不是 `TechnicalIndicatorService.calculateATR` 的 Wilder 平滑）。
- 1R＝平均成本 − 停損價。
- 時間停損（v3.3）：進場日之後的 8 個交易日內，收盤一次都沒有 ≥ 平均成本 + 1R，第 8 個交易日收盤後即到期；期間只要有一天收盤到過 +1R，時間停損就解除。天數放在新參數檔。
- 依據：2026-08-07 停損回測，2.0 × ATR 配「8 日內未達 +1R 才出場」扣成本後每筆約 +1.6%，固定 4% 停損配 5 日約 −0.2%。限制：樣本 14 個月、多頭為主的單一行情，訊號是結構 B 加強者榜量能動能的骨架，不是完整漏斗；所以倍數與天數都放參數，日後改一處即可。
- D 收盤低於停損價→事件「收破停損價」；時間停損到期→事件「時間停損到期」。持有天數與「第幾天／共 8 天」照寫。
- 強者榜上沒持有的股票不做守門價：那些守門價過去寫在決策表上，App 沒存，也沒記錄股票何時放進強者榜。除名照用「連 2 日收破月線」。

## 入口

今日頁的大盤摘要條下方放一張卡：「收盤摘要・11/19・持股 2 檔・事件 5 檔 →」，點進摘要頁。新增路由常數放 `AppRoutes`。

## 文字

畫面字走翻譯檔（中、英），而且要過 `no_investment_advice_copy_test`（禁「推薦」「進場」「停損」「停利」等；英文禁 entry、stop loss 等），不為這頁開放行。本文件的「停損價」「時間停損」「進場前提」是概念名稱，畫面上的用語是：

| 概念 | 畫面用語 |
|:--|:--|
| 持股停損價 | 成本守門價（與個股頁「最新收盤 − 2×ATR」的守門價不同值，名稱分開） |
| 時間停損到期 | 8 日未達 +1R |
| 進場前提 | 前提條件 |
| 結構 C 突破（突破日不進場） | 結構 C 突破（突破當天） |

## 留給實作者

- 資料讀取的批次方式（現有 `getPriceHistoryBatch`、`getInstitutionalHistoryBatch`、營收批次查詢可用）與 provider 的切法。
- 計算放在 domain 層的純函式，每條條件各自可測。
- 列的版面、事件的顏色與圖示；手機寬度要排得下。
- 入口卡在沒有自選也沒有持股時的樣子。
