# 今日頁資訊層次重排＋獨立大盤頁 — 設計

## 背景

今日頁目前由上而下是：提示條 → 大盤總覽卡 → 族群排行 → 月營收／季報入口 → 釘選論點 → 今日訊號。
大盤總覽卡內含指數、市場情緒、漲跌家數、市場廣度、AD 騰落線、成交額、法人動向、融資融券、籌碼異動，
手機寬度下約佔 4.5 屏，「今日訊號」要捲到約第 6 屏才出現（2026-09-25 Mac 窄視窗實機截圖）。
新使用者打開 App 看到的是大盤儀表板，而不是這個 App 的核心——訊號。

## 目標與成功標準

- 第一屏回答「今天有什麼要看的」：條件式提示 → 一行大盤摘要 → 今日訊號
- **量化標準**：390×844 視窗、條件式提示不超過兩條時，「今日訊號」標題不需捲動即可見（widget 測試斷言其位置在視窗內）
- 保留「大盤 → 個股」由上而下的閱讀順序：大盤仍在訊號之前，只是縮成摘要
- 完整大盤儀表板內容一項不少，改由摘要條點進獨立頁面

## 非目標

- 儀表板各區塊的內容與排版不改（整個 `MarketDashboard` 原樣搬到新頁）
- 族群排行、月營收／季報入口、釘選論點的內部不改，只改在頁面中的位置
- 色彩語意修正（分數徽章、籌碼異動張數、融資增減）與分數說明入口另案處理
- 不新增底部導覽分頁

## 版面（今日頁，由上而下）

| 順序 | 區塊                                                       | 變動                 |
|:-----|:-----------------------------------------------------------|:---------------------|
| 1    | 標題列、最後更新／資料日期                                 | 不變                 |
| 2    | 條件式提示：更新進度、資料落後、歷史建置中、自選跌破／站回 | 不變                 |
| 3    | **大盤摘要條**（新）                                       | 取代原大盤總覽卡     |
| 4    | 部分錯誤橫幅、釘選論點                                     | 位置不變（相對順序） |
| 5    | 今日訊號：標題、模式分頁、清單                             | 往上移到摘要條之後   |
| 6    | 族群排行、月營收入口、季報入口                             | 從訊號之前移到之後   |
| 7    | 常駐短版免責聲明、底部間距                                 | 不變                 |

取捨：族群排行原本刻意放在個股之前（程式碼註解「族群決定 80%」）。它自身高約 250px，放在前面會把
訊號擠出第一屏，故移到訊號之後；仍在今日頁、內容不變。

## 元件

### 1. 情緒分數抽成共用函式

`MarketDashboard` 的私有方法 `_computeSentiment` 與取主指數的邏輯（上市取加權指數、上櫃取櫃買指數）
抽成純函式，輸入 `MarketOverviewState` 與市場代碼，輸出情緒／主指數。儀表板改呼叫它，**行為不變**；
摘要條呼叫同一份，確保兩處顯示的數字一致。

### 2. `MarketSummaryStrip`（今日頁）

輸入：`marketOverviewProvider` 的狀態（與原大盤卡同一來源，不新增任何載入）。

| 狀態                                      | 顯示                                                                                                      |
|:------------------------------------------|:----------------------------------------------------------------------------------------------------------|
| 有資料                                    | 第一行：`加權 48,024.60 -0.28%・櫃買 {值} {漲跌%}`（每組一個 Text.rich，只在組與組之間換行）；第二行：`上市 情緒 37 恐懼・漲 408 跌 667`；右側 `›` |
| 主指數為資料庫備援值（`indexStaleNames`） | 該指數後附「非即時」標記（沿用現有語意）                                                                  |
| 部分區塊失敗（`failedSections` 非空）     | 數字下方獨立一行警示圖示與「N 區塊載入失敗」（窄螢幕不溢出）；缺的欄位以「—」呈現，不靜默省略 |
| 已有資料但重新整理失敗（`error` 非空）   | 舊數字照顯示，數字下方一行錯誤訊息（與大盤頁儀表板頂端同一條警示）                                  |
| 情緒算不出（資料不足）                    | 情緒欄位顯示「—」                                                                                         |
| 載入中且無資料                            | 與摘要條同高的骨架                                                                                        |
| 無資料且有錯誤                            | 沿用現有錯誤列（錯誤訊息＋重試），從原大盤卡位置搬來                                                      |
| 無資料、無錯誤、非載入中                  | 不渲染（與現行為一致）                                                                                    |

點擊整條 → 推入 `/market`。漲跌數字配色依現行股價紅綠慣例。

### 3. `/market` 大盤總覽頁（新）

- 路由：`AppRoutes.market = '/market'`，Shell 外全螢幕（比照 `/industry`）
- 內容：AppBar「大盤總覽」＋ 可下拉重新整理的捲動區，放入原樣的 `MarketDashboard(state:)`
- 讀同一個 `marketOverviewProvider`：從今日頁點進來時資料已在，不重新載入；下拉重新整理呼叫 `loadData()`
- 載入中／錯誤狀態與原今日頁大盤卡相同
- 上市／上櫃切換、寬螢幕並排雙欄等儀表板既有行為全數保留

## 資料流

不新增 provider、不新增 API 呼叫。`marketOverviewProvider` 的載入時機（今日頁啟動、更新完成、回前景）不變；
摘要條與大盤頁都只是讀取者。

## 測試

- 共用函式：與原 `_computeSentiment` 等價（同一組 state 輸入、數值相同）；情緒資料不足回 null
- 摘要條：有資料／非即時／部分失敗／情緒不足／載入中／錯誤可重試，各一個 widget 測試
- 點擊摘要條導向 `/market`
- 大盤頁：渲染 `MarketDashboard`；下拉重新整理呼叫 `loadData()`
- 今日頁：
  - 順序斷言：「今日訊號」標題在族群排行之前、在摘要條之後
  - 量化標準：390×844、兩條提示時「今日訊號」標題在視窗內
  - 既有「要跑更新時不必先等大盤的網路載入」測試維持綠
- golden：今日頁 light／dark 重新產生（刻意的版面變更），新增大盤頁 golden
- 每個新增條件做 mutation 驗收（拔掉即紅）

## 風險

- **使用者習慣**：每天看完整大盤的人多點一下。摘要條保留最關鍵的三個數字，減輕影響
- **寬螢幕**：Mac 全寬視窗原本在今日頁就看得到並排雙欄儀表板，改後在大盤頁才看得到。刻意不為寬螢幕另做版面，保持單一行為
- **golden 變更範圍大**：今日頁 golden 必然全換，審查時以截圖比對新版面，不以「golden 綠」當作正確的證據
